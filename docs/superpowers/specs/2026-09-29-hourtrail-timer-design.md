# HourTrail 首版详细设计：实时计时与可靠核对

日期：2026-09-29。状态：供评审的设计规格，尚未实现。

本文细化 [项目设计](../../PROJECT_DESIGN.md)。首版以实时计时为主，手动补录和修正为辅。基础技术选型、离线运行、完整备份和 Windows/macOS 迁移要求沿用项目设计。

## 1. 已确认方向与本次设计默认值

用户已确认：一个任务可包含多个工作时段；开始、暂停、继续、结束是主要操作；关闭窗口后保留后台计时；休眠后由用户核对中断时间；异常退出留下的未结束记录进入待核对。

以下是为使流程完整而提出的默认值，属于本次文档评审范围：

- 唤醒后不自动恢复计时。用户核对后选择继续，或者暂存待核对并开始其他任务。
- 一条记录只要仍有未解决的问题，整条记录都不进入正式报表。已确认部分仍在详情中显示。
- 点击结束立即固定结束时间并释放活动任务位置，随后核对保存。关闭核对面板不会丢失记录或继续累计。
- 锁屏和屏幕熄灭不等同于系统休眠，不自动暂停。首版不检测键鼠活动。
- 默认中文界面、24 小时制、周一为每周起点。首次启动提出系统时区作为候选，用户确认后保存为统计时区。

## 2. 首版范围

首版必须形成“开始工作 → 后台计时 → 核对 → 月度报表 → 备份迁移”的完整流程。

包含实时计时、托盘、休眠与异常恢复、手动补录、多时段编辑、日历、月度报告、CSV、完整备份、替换恢复、自动快照和回收站。

首版不包含项目层级、团队审批、薪资计算、云同步、键鼠监测、全局快捷键、开机自动启动和日历拖动修改。任务标题允许重复，不建立独立的任务模板表。同一天可以有多条记录。

## 3. 页面和操作

### 3.1 工作台

默认页面上方固定显示计时卡片，下方为日历。导航包含工作台、月度报告和设置；待核对列表由固定入口打开，并显示数量。

| 当前情况 | 卡片内容 | 主操作 |
| --- | --- | --- |
| 没有活动任务 | 标题输入、开始按钮 | 开始工作 |
| 正在计时 | 标题、本次累计时长、当前时段起点 | 暂停、结束 |
| 已暂停 | 标题、已累计时长、暂停标识 | 继续、结束 |
| 存在待核对记录 | 独立提示条，不冒充正在计时 | 打开核对列表 |

开始必须有非空标题。备注可稍后补充。按钮操作期间禁用重复提交，成功反馈以本地事务提交为准。计时卡片显示到秒，日历和报表显示到分钟。

日历的每个工作时段是一条事件。正在计时使用动态结束位置，并标注“计时中”；待核对使用文字和不同样式同时区分。点击事件打开所属记录。空白日期入口用于手动补录，起止时间按统计时区输入，结束日期可独立选择。

切换任务采用“结束当前任务，再开始新任务”。暂停任务仍占用唯一活动位置，不允许同时保留多个暂停任务。

### 3.2 结束与核对

点击结束时，先在事务中关闭开放时段，将记录转为 `needs_review`，再展示核对面板。面板显示各段起止日期时间、累计时长、备注和问题列表。

没有异常时，用户点击“确认保存”即可完成。有异常时，必须逐项处理。关闭面板等同于稍后核对，记录仍保存在本地。允许立即开始另一个任务。

修改起止时间后实时预览时长；保存时由 Rust 检查顺序、日期和重叠。冲突提示包含相冲突的记录标题、时段和跳转入口，不自动裁剪用户记录。

已完成记录可以编辑。保存失败时保留旧记录和当前表单。活动记录只允许修改标题和备注；修改历史时段必须先结束当前计时。

### 3.3 托盘和退出

关闭按钮隐藏窗口并保留 Rust 进程。首次隐藏给出一次应用内说明。托盘或菜单栏提供打开窗口、当前状态、暂停或继续、结束、退出。

托盘“结束”固定结束时间后打开核对面板。没有活动任务时，暂停、继续和结束不可用。托盘创建失败时不隐藏最后一个窗口，并说明后台入口不可用。

主动退出且存在活动任务时，提供“结束并核对”“保留待核对并退出”“取消”。第一项完成核对保存后退出；第二项关闭当前开放时段、转为待核对，事务成功后退出。退出等待期间不接受新的开始操作。无活动任务时可直接退出，待核对记录不会阻止退出。

系统关机、强制结束或崩溃不依赖确认框保住数据，统一由持久化检查点和下次启动恢复处理。

### 3.4 删除与找回

活动记录不能删除。其他记录软删除后不参与报表，在回收站中可以找回。首版不提供永久删除或自动清空。恢复已完成记录时再次校验重叠，冲突则保持删除状态并允许用户以待核对状态找回。短暂的撤销提示和回收站使用同一恢复规则。

## 4. 计时状态机

`idle` 表示没有活动记录，不存入 `work_entries.status`。记录状态为 `running`、`paused`、`needs_review`、`completed`。软删除是独立字段。

| 原状态 | 事件 | 新状态 | 同一事务内的动作 |
| --- | --- | --- | --- |
| idle | 开始 | running | 创建记录、开放时段和运行检查点 |
| running | 暂停 | paused | 关闭开放时段，清除运行检查点 |
| paused | 继续 | running | 新建开放时段和检查点 |
| running / paused | 结束 | needs_review | 关闭开放时段，清除活动位置 |
| running | 休眠或发现计时异常 | needs_review | 保留可信部分，创建中断核对项，清除活动位置 |
| needs_review | 确认保存 | completed | 应用核对决定，验证全部区间 |
| needs_review | 核对并继续 | running | 解决全部核对项；活动位置空闲时新建时段 |
| completed | 编辑并保存 | completed | 整条记录及所有时段原子更新 |

暂停期间休眠仍保持暂停，没有工作中断区间。进程重启后遗留的 `paused` 转为 `needs_review`，保留已有时段，不补入离线时间。遗留的 `running` 执行异常恢复。

核心不变量：

1. 一个工作区最多一条非删除的 `running` 或 `paused` 记录。
2. `running` 恰有一个开放时段，其他状态没有开放时段；迁移来的旧待核对数据可例外，见第 8 节。
3. 暂停、结束、核对和编辑都不能产生零长度或负长度时段。发生在同一毫秒的开始与停止移除空时段，保留待核对记录供删除或补充。
4. 非删除的已完成记录，以及活动记录中的实际时段，构成冲突检查集合；开放时段按 `[startAt, +∞)` 阻止手动录入穿越正在计时的区间。待核对区间不占用时间，但转为正式记录时必须重新检查。
5. 开始或继续时检查已有正式区间是否包含当前时刻。手动补录不接受晚于命令执行时刻的结束时间。
6. 所有入口共用 Rust 状态转换服务。前端、托盘和系统通知不能各自维护独立计时状态。

## 5. 休眠、异常退出与时钟变化

### 5.1 检测与持久化

平台适配器将系统休眠和唤醒转为内部事件。Windows 候选接入点为 `PBT_APMSUSPEND` 和 `PBT_APMRESUMEAUTOMATIC`；macOS 候选接入点为 `NSWorkspace` 的 sleep/wake 通知。原生事件提供线索，不保证每次都有完整的开始和结束配对，发布前必须在两种系统实测。[1][2][3][4]

Rust 在正在计时时每 15 秒保存检查点，包括当前时段 ID、最近可信 UTC 时间和进程会话 ID。单调时钟只用于本进程内的间隔比较，不跨重启持久化后相减，也不将回调次数换算为工时。

回调间隔超过 60 秒且没有完整电源事件时，标记“运行中断”，不直接声称用户休眠。正常非休眠采样中，墙上时钟与单调时钟的增量偏差超过 2 秒时，标记“系统时间变化”。这两个阈值是初始保守默认值，可能导致额外核对，不能用来证明每次休眠都被检测到。

### 5.2 休眠后的核对

收到休眠通知时，在可写入的情况下关闭当前时段并创建开放的中断核对项。记录转为待核对。唤醒时补充观察到的终点。重复通知根据同一会话和未解决核对项合并，不能产生重复工作时段。

唤醒后不自动开启时段，即使系统只是自动唤醒执行后台任务。主界面和托盘显示待核对提示；用户打开后可以：

- **计入：** 将所选中断区间转换为工作时段。
- **排除：** 保留中断说明，不新增工作时段。
- **修正：** 调整区间，允许保留其中多个不连续的工作时段。
- **稍后处理：** 保持待核对，不计入正式报表。

处理完后可“确认保存”或“核对并继续”。继续以用户点击时刻为新起点，唤醒到点击之间的等待时间不自动计入；如果该段也在工作，可在核对中手动补入。存在其他活动任务时，只允许保存。

例：09:00 开始，10:00 休眠，10:30 唤醒，10:35 点击继续。排除休眠时保留 09:00–10:00，并从 10:35 新建时段；选择计入则额外保留 10:00–10:30。10:30–10:35 需要用户明确补入。

### 5.3 不完整事件与异常退出

运行记录在重启后仍为 `running`，说明上次没有完成收尾。将开放时段关闭到最后可信检查点，余下区间作为建议核对范围，终点显示本次启动时间并明确标注“检测时间，非工作结束时间”。不得自动将整段离线时间计为工作。

若休眠事件未成功写入，唤醒时也采用最后可信检查点作为候选边界。边界可能提前，界面允许用户修正，不能展示成精确的休眠时间。

系统时间回拨导致观察终点早于候选起点时，观察值仅保存在核对证据中，不创建非法工作区间；用户必须给出合法日期时间。存储错误时显示持久化失败状态，阻止新的开始或继续；重新可写后先核对不确定区间，不能静默宣称仍可靠计时。

## 6. 时间与报表规则

统计使用 UTC 毫秒区间，按选定 IANA 时区的当地日和月边界切分。跨午夜不自动结束任务，也不将休息计入。所有正式统计只来自非删除的 `completed` 记录。

运行、暂停和待核对分别显示数量及可确定时长，开放或未解决区间不显示成精确的已完成工时。待核对记录中的可信时段也不计入正式合计，以保持“完成后整条入账”的一致规则。

统计聚合毫秒后再格式化：页面小时和分钟向下取整，详情可查看秒；CSV 保留精确 `durationMs`，`decimalHours` 四舍五入到 6 位。逐行显示数相加可能与汇总显示有微小差异，核对以毫秒列为准。

修改统计时区需要预览受影响的日期和月度分配，经用户保存后整体重算。UTC 区间和总实际时长不改变。存在活动任务时不允许修改时区；未保存的表单必须关闭或放弃，保存命令还要检查设置版本。无法识别的时区必须报错，不替换为系统时区。

本地时间在夏令时切换中重复出现时，明确选择 UTC 偏移；不存在的当地时间要求重选。前端只做输入提示，Rust 负责时间解析和正式统计。

CSV 每行表示一个时段在某个当地日内的部分；`startAt` 和 `endAt` 使用带偏移的 ISO 8601 时间。使用 UTF-8 BOM 和 CRLF，文本字段按 CSV 规则转义，用户文本中的公式前缀进行表格安全处理，备份保留原文。

## 7. 数据模型与边界

| 表 | 新增或明确的字段 | 约束 |
| --- | --- | --- |
| `work_entries` | `source: manual/timer`、四种状态、`version` | version 用于编辑冲突；删除和状态独立 |
| `work_segments` | `id, entry_id, start_at, end_at` | end_at 仅在运行或兼容旧待核对数据时可空 |
| `review_items` | `id, entry_id, reason, candidate_start_at, candidate_end_at, boundary_quality, resolution, resolved_at` | reason 为 sleep、interruption、clock_change、recovery；resolution 为 unresolved、included、excluded、adjusted |
| `timer_runtime` | 单行活动运行记录、`segment_id, process_session_id, last_checkpoint_at` | 设备本地运行证据，不作为可移植计时器 |
| `app_metadata` | `workspace_id, schema_version, mutation_revision` | 每次领域写入递增修订，恢复后产生新修订 |
| `settings` | 统计时区、每周起点、设置版本 | 可移植偏好 |
| `device_settings` | 窗口状态、快照目录、上次导出信息 | 不随完整备份迁移 |

核对项的候选时间是观察证据，可以为空或在时钟异常时逆序，不能直接用于工时计算。`boundary_quality` 为 `observed` 或 `estimated`。用户决定保留的实际时段只存于 `work_segments`，通过同一事务应用核对并设置 resolution，不重复累加证据字段。

初始输入上限：标题去除两端空白后 1–200 个 Unicode 码点，备注最多 10,000 个码点，每条记录最多 1,000 个时段和 1,000 个核对项。已完成记录至少包含一个正长度时段；待核对记录允许没有时段。时间范围为 UTC 2000-01-01（含）至 2100-01-01（不含），超范围时提示不支持。导入最多 100,000 条记录、500,000 个时段和 500,000 个核对项，总文件仍受 50 MiB 上限约束。

时钟适配器、计时服务、记录服务、报表服务和备份服务各自独立：

- 时钟适配器提供 UTC、单调时间及电源事件，可用测试时钟替换。
- 计时服务拥有状态转换和检查点，依赖时钟及数据库。
- 记录服务拥有编辑、删除、核对和重叠校验，复用同一验证器。
- 报表服务只读取领域记录，不依赖界面或操作系统时区。
- 备份服务使用明确的传输对象，复用记录验证和报表计算。

写入通过统一的写锁及事务执行。使用数据库约束再次保证单一活动记录。应用以单实例启动，重复启动聚焦现有窗口；仍须在数据库层拦截跨入口竞态。

## 8. 备份、恢复与快照

### 8.1 可移植格式

`formatVersion: 1` 尚未发布，本次完善它的合同，不宣称已有生产备份兼容。增加顶层 `reviewItems` 数组，记录核对原因、候选边界和处理结果。字段对应第 7 节并使用 camelCase。工作记录的设备内 version 不导出，导入时重新生成；稳定的业务 ID 保留。

备份仍只允许 `completed` 和 `needs_review`。正在计时或暂停时，先明确选择结束并核对，或者结束为待核对，再导出。不在序列化过程中偷偷变更计时状态。`timer_runtime` 不导出，迁移后不自动运行。

为了读取初步设计中的样例，缺少 `reviewItems` 时按空数组处理。旧 `needs_review` 中的开放时段保留，恢复后不能累计；核对时必须填写结束时间或删除该时段才能完成。已完成记录不得有开放时段或未解决核对项。

### 8.2 恢复一致性

沿用验证、不可变预览、修订绑定、安全快照、事务替换的流程。检查点更新不改变可移植数据修订；状态转换和核对更新会改变。执行恢复时再次检查无运行或暂停任务，并清空设备运行残留。

预览展示待核对原因及数量。导入不把源设备的休眠候选区间扩展到当前时间。核对信息与 ID 必须在 Windows 和 macOS 间完整往返。

### 8.3 自动快照与本地找回

启动成功且存在数据时创建快照，此后有领域修改时最多每小时创建一次。保留最近 7 个自动快照，只有新快照创建并验证成功后才清理旧快照。恢复前的安全快照独立保留，不参与这 7 个的自动轮替，用户可在管理页删除。

快照失败不撤销已经保存的工时，但显示可操作错误；恢复前快照失败则阻止恢复。自动快照不能替代用户另存到其他位置的完整备份。

“从本地快照恢复”先只读验证并提取领域数据，经支持的模式迁移后进入同一替换预览流程。快照中的活动记录转换为待核对，不自动恢复运行。无法读取的较新模式拒绝恢复，不覆盖当前数据库文件。当前设备设置保持不变；数据库已损坏时进入恢复页面，保留损坏文件副本后才能创建新工作区。

## 9. 应用命令与错误处理

以下是应用合同，不是 Tauri 内建 API。领域写入带 `requestId` 和当前 `workspaceRevision`，记录编辑还带 `expectedEntryVersion`。Rust 在事务内验证版本；计时命令使用服务端读取的时刻，手动修正才接受用户指定时间。

成功返回更新后的数据和修订。为处理响应丢失，写入事务同时保存 requestId、输入摘要和结果于设备本地操作日志；同一 requestId 和相同输入重试返回原结果，不再次执行。不同输入复用同一 ID 报错。日志保留 7 天，超过期限的客户端不重放旧操作，先刷新状态。重复检查先于版本检查。

| 命令 | 主要输入 | 返回和行为 |
| --- | --- | --- |
| `get_timer_state` | 无 | 活动记录、开放起点、已关闭时段总时长、服务端当前时间及修订 |
| `start_timer` | title、可选 note | 创建记录和开放时段 |
| `pause_timer` / `resume_timer` | entryId | 返回新状态；非法转换返回 STATE_CONFLICT |
| `stop_timer` | entryId | 转待核对，返回已固定的全部时段 |
| `resolve_entry` | entryId、最终时段、各核对项决定、动作 complete/continue | 全部问题解决后完成或继续 |
| `save_entry` | 手动记录或已完成记录的全部字段 | 验证并保存，不能覆盖活动计时字段 |
| `list_entries` | 起止时间、状态、是否删除、游标 | 区间采用左闭右开，返回分页记录及核对项 |
| `list_review_entries` | 游标 | 返回待核对记录，包含无时段记录，避免从日历消失 |
| `delete_entry` / `restore_entry` | entryId；恢复可选择待核对 | 软删除或验证后恢复 |
| `preview_reporting_zone` / `set_reporting_zone` | IANA 时区；保存带预览 token | 比较历史分配，修订未变时应用 |
| `get_month_report` | YYYY-MM | 明确月份、时区、正式总毫秒、每日明细、未完成分类 |
| `export_month_csv` / `export_backup` | 月份（CSV）、用户选择的目标 | 成功文件位置和统计；取消独立返回 |
| `inspect_backup` / `restore_backup` | 文件；恢复带 token 和替换确认 | 预览 token 绑定内容及修订，10 分钟过期，成功后失效 |
| `create_local_snapshot` / `list_local_snapshots` | 无 | 创建结果或本地快照列表 |
| `inspect_local_snapshot` | 本地快照标识 | 返回同一种恢复预览，使用 restore_backup 应用 |

本地操作日志增加为 `operation_receipts` 表，不进入备份。恢复成功清除旧工作区回执并记录本次恢复回执，防止旧界面重放历史命令。恢复、新建工作区和设置变化都使旧表单版本失效。

错误统一返回 `{ code, message, fieldErrors, details, retryable }`。基础错误包括 VALIDATION、OVERLAP、ACTIVE_TIMER、STATE_CONFLICT、STALE_REVISION、UNRESOLVED_REVIEW、CLOCK_UNCERTAIN、IO_PERMISSION、DISK_FULL、UNSUPPORTED_FORMAT、STALE_PREVIEW。details 只包含可展示字段，不暴露数据库内部语句。

计时操作不做乐观成功更新。命令超时后先查询状态，用相同 requestId 查询或重试结果。事件只提示前端刷新，事件丢失时通过重新打开窗口后的查询恢复一致性。检查点不逐次发送界面事件。

## 10. 验收与交付顺序

| 场景 | 预期结果 |
| --- | --- |
| 09:00 开始，12:00 暂停，13:30 继续，18:00 结束并确认 | 两个时段，总计 7 小时 30 分钟 |
| 窗口关闭 20 分钟后重新打开 | 计时继续，状态与托盘一致 |
| 主窗口与托盘同时开始或暂停 | 只有一次有效转换，不生成重复时段 |
| 10:00 休眠，10:30 唤醒 | 生成候选核对项，未自动开始，也未入正式统计 |
| 休眠事件缺失或重复 | 使用可解释的估计边界或合并事件，不重复入账 |
| 暂停后休眠 | 不产生休眠工作时间，仍保持暂停 |
| 崩溃后隔天启动 | 可信时段保留，离线区间待核对，不整夜累计 |
| 系统时间回拨 | 不生成负时长，要求核对 |
| 点击结束后关闭面板 | 结束时刻固定，记录待核对，新任务可开始 |
| 核对后试图计入与其他记录重叠的区间 | 拒绝并定位冲突，不自动裁剪 |
| 删除后撤销但出现新重叠 | 不恢复为正式工时，可恢复为待核对 |
| 写入失败或命令响应丢失 | 不显示虚假成功，相同请求不能重复创建记录 |
| 待核对记录跨平台备份往返 | ID、证据及所选时段保留，无自动计时 |
| 恢复或改时区后旧表单提交 | 拒绝过期写入，要求刷新 |
| 跨日、跨月、夏令时、CSV | 日月分配正确，精确毫秒合计一致 |

交付按依赖顺序分四步：

1. 用可替换时钟完成领域模型、状态机、冲突验证及报表测试。
2. 接入持久化、检查点、平台休眠事件、托盘和恢复流程，在 Windows x64 与 macOS arm64 验证生命周期。
3. 完成工作台、核对、补录、回收站和月度报告，验证操作失败时数据不丢失。
4. 完成 CSV、完整备份、本地快照和双向迁移测试后发布。

这些是验收要求，不是已执行的测试。日历供应组件沿用原文的暂定解释；签名、安装包和平台事件的可用性必须在实现阶段验证，不能以文档推断替代实机测试。
