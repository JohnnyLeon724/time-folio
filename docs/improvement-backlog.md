# HourTrail 功能与体验优化清单

未保存修改保护和时间冲突定位已实现并通过组件测试与浏览器验证。桌面实机验收仍待完成；后续功能建议优先考虑时间录入提速。计时、核对、日历、报表和备份已有主流程，后续优化以减少误操作和重复操作为目标。

本文整理 2026-10-03 的代码审阅建议，供后续排期使用。已实现条目在下文标明，其余条目仍待实施或验证。现有功能说明见 [README](../README.md)，测试与发布状态以[发布验收记录](release-checklist.md)为准。

## 编辑安全与录入效率

### 未保存修改保护

现状：[编辑面板](../src/features/entries/entry-sheet.tsx)比较标题、备注、时段和核对选项，关闭存在未保存修改的面板前要求确认。保存期间禁止重复提交和关闭，失败后保留输入。

关闭确认默认聚焦“继续编辑”，选择“放弃修改”才会关闭。当前保护限于面板内存中的输入；持久化草稿可另行设计，避免把草稿误当成已确认工时。

验收标准：

- [x] 未修改内容时可直接关闭，不额外打断操作。
- [x] 修改后通过关闭按钮、Escape、遮罩或取消离开时，执行一致的保护逻辑。
- [x] 选择继续编辑后，输入、时段和核对选项保持不变。
- [x] 保存成功后正常关闭；保存失败后仍能修改并重试。
- [x] 正在保存时不能重复提交或绕过已有关闭限制。

### 时间冲突定位

现状：[后端冲突校验](../src-tauri/src/domain/validation.rs)返回当前时段 ID、冲突时段 ID、记录 ID、标题及起止时间。编辑面板高亮对应时段，并显示统计时区中的完整日期和时间；记录内部重叠会标出双方时段。

外部冲突可打开[只读详情](../src/features/entries/conflict-record-dialog.tsx)，返回后保留当前输入。详情读取失败可重试，记录不存在时明确提示。修改时段后清除过期提示，再次保存仍由后端最终校验，不自动裁剪或覆盖已有工时。

验收标准：

- [x] 明确指出当前哪一段与哪条记录重叠，并按统计时区显示时间。
- [x] 查看冲突记录时，不丢失当前未保存输入；与修改保护协同处理。
- [x] 修正时段后能重新提交，清除过期提示。
- [x] 跨午夜、多时段、同名任务仍能准确定位。

### 时间录入提速

现状：[日期时间组件](../src/components/date-time-picker.tsx)分别选择时、分、秒；编辑面板新增时段使用固定的 09:00 至 10:00 默认值。

建议：支持直接输入 `09:30`，提供前后调整 5 分钟或 15 分钟的操作。新增时段优先衔接上一段结束时间，并清楚显示日期变化。具体默认时长在实现前确认。

验收标准：

- [ ] 直接输入、下拉选择和快捷调整使用同一份表单值。
- [ ] 保留已有秒级数据，不因只编辑分钟而无提示地清零秒数。
- [ ] 不合法输入有就地提示，不能保存结束早于开始的时段。
- [ ] 跨午夜时日期明确变化，按统计时区解析，保持现有夏令时歧义处理。
- [ ] 新增时段不会静默覆盖已有时段，保存时仍校验重叠。

## 报表与数据反馈

### 图表与明细联动

现状：[每日工时图表](../src/features/reports/daily-duration-chart.tsx)支持时长提示；[工作明细](../src/features/reports/work-details-table.tsx)支持任务搜索、排序、按日展开和分页，两者尚未联动。

建议：点击柱形筛选并展开当天明细，显示当前日期筛选及清除入口；点击报告中的待核对统计卡进入核对列表。

验收标准：

- [ ] 鼠标和键盘都能选择日期、清除筛选。
- [ ] 日期筛选与任务搜索共同生效，分页回到有效页。
- [ ] 切换月份后不保留不适用的日期筛选。
- [ ] 无匹配记录时说明原因，不能表现为加载失败。

### 搜索与导出范围提示

现状：工作明细搜索只影响表格；[导出入口](../src/app/app.tsx)调用整月导出，按钮文案为“导出工时表”。

建议：先将现有操作明确标为“导出整月”。如增加“导出当前筛选结果”，需让筛选条件成为明确的导出参数，并统一界面与后端的过滤规则。

验收标准：

- [ ] 导出前可辨认月份、筛选范围及记录数量。
- [ ] 筛选导出包含全部匹配时段，不仅是当前分页中显示的行。
- [ ] 保持现有中文五列、每时段一行、跨午夜拆日及文本转义规则。
- [ ] 导出的时段与界面筛选结果逐项一致，精确时长保持一致。

### 备份状态与失败反馈

现状：已有自动快照和手动备份；[设置页](../src/features/settings/settings-page.tsx)首次读取快照列表失败时忽略异常，可能让用户误以为没有快照。

建议：区分加载中、空列表和加载失败，提供重试入口；展示最近成功备份或快照的时间，失败时说明原因。外部备份与本地快照分别标注，避免混淆保护范围。

验收标准：

- [ ] 读取失败显示错误及重试入口，不显示为空列表。
- [ ] 最近成功时间来自实际成功结果，不在失败时更新。
- [ ] 创建、删除、恢复后状态与列表同步更新。
- [ ] 快照轮替和失败保留旧文件等专项检查，统一记录到发布验收清单。

## 后续功能与性能

### 最近任务与快捷复用

现状：[计时输入](../src/features/timer/timer-card.tsx)以自由输入标题为主。

建议：展示最近使用的任务名称，选择后创建新的计时记录。默认只复用标题，不复制旧时段或核对状态。

验收标准：

- [ ] 可以搜索和键盘选择最近任务，也可以继续自由输入。
- [ ] 同名标题合理去重，标题仍可编辑。
- [ ] 开始计时生成新记录，不修改原任务记录。
- [ ] 有活动任务时保持现有单一活动记录约束。

### 周报与任务汇总

现状：[报告页](../src/features/reports/monthly-report-page.tsx)以月份和每日工时为主。

建议：增加周维度和任务维度汇总。实施前明确每周起始日及“同一任务”的识别规则，避免仅凭同名标题误合并。项目、标签属于可选扩展，待分类需求明确后再设计。

验收标准：

- [ ] 周、日及月汇总使用同一统计时区和已确认工时规则。
- [ ] 跨周、跨月时段按边界正确切分，汇总不重复累计。
- [ ] 任务汇总支持追溯原始记录，明确同名任务的归组方式。

### 历史数据性能优化

现状：[记录读取](../src-tauri/src/db/records.rs)查询全部工作记录；[工作区接口](../src-tauri/src/commands/mod.rs)将记录交给前端使用。长期积累后的性能影响尚未量化。

建议：先使用一万条合成记录测量启动、月份切换、搜索、报告生成及内存占用。根据瓶颈决定是否按日历可见范围读取、让核对与回收站独立分页，或继续拆分页面资源。

验收标准：

- [ ] 记录测试机器、数据分布及优化前后的测量结果，再确定性能目标。
- [ ] 日历按实际可见范围加载，跨月周视图不遗漏邻月记录。
- [ ] 分页或按范围读取不削弱全局时间冲突校验。
- [ ] 报告、导出与备份仍覆盖各自完整数据范围。

## 桌面验收与实施边界

桌面验收使用独立测试数据库，具体检查项和结果继续维护在[发布验收记录](release-checklist.md)，不在本文另建完成状态。重点覆盖托盘操作、休眠唤醒、异常退出恢复、备份恢复，以及在表格软件中打开 CSV。浏览器示例数据验证不能替代桌面实机操作。

每个独立功能完成后，连同必要测试原子提交；避免把编辑保护、报表交互和数据读取改造混在一次提交中。后续功能建议从时间录入提速开始。涉及导出范围、任务身份或后端查询接口的变化，应先明确数据规则及兼容性，再开始实现。
